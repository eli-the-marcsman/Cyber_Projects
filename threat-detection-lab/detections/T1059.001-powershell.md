## What the Attack Did
Test 10 wrote a Base64 encoded PowerShell payload into a registry
key and executed it from memory — a common fileless malware technique.
Test 17 executed obfuscated PowerShell using the -EncodedCommand (-e)
flag, which attackers use to hide malicious commands from basic
string-based detection.

## False Positive Considerations
- Legitimate administrative scripts may use -EncodedCommand
- Software installers sometimes write Base64 values to registry
- Distinguish by checking parent process and user context
- Admin running known scripts during maintenance window = low risk

## Triage Steps
1. Identify the user and process that executed the PowerShell command
2. Review the full CommandLine field for the encoded payload
3. Decode the Base64 string to inspect the actual command
4. Check if the parent process is expected (e.g. legitimate scheduler)
5. Search for related activity from the same process GUID

## Escalation Decision
**Escalate: Yes** — Base64 encoded PowerShell combined with
file drops in temp directories indicates likely malicious activity.
Escalate to Tier 2 for full investigation unless confirmed
legitimate admin activity.

## Analyst Notes
Test 1 (Mimikatz download) was blocked by Windows Defender AMSI
before execution. This demonstrates a working preventive control
but also a logging gap — the block was not captured in Wazuh.
Recommend adding Windows Defender event channel to agent config.
