## What the Attack Did
Created a scheduled task designed to execute automatically
on a recurring basis. Attackers use this technique to maintain
persistent access to a system — ensuring their code runs even
after reboots without requiring a service installation or
registry modification.

## False Positive Considerations
- Legitimate software frequently creates scheduled tasks during
  installation (Windows Update, antivirus, browsers)
- IT automation tools create tasks as part of normal operations
- Key differentiators: unexpected task name, unusual binary path,
  task created outside business hours or change window

## Triage Steps
1. Note the task name and the binary it executes
2. Check if the task was created during a known change window
3. Verify the binary path exists and is a known legitimate file
4. Check hash of the binary against threat intelligence
5. Review what account created the task and whether it's expected

## Escalation Decision
**Escalate: Yes if** — task name is randomized, binary is in
a temp or user directory, or task was created outside business
hours with no corresponding change ticket.

## Analyst Notes
Scheduled task creation is extremely common in enterprise
environments. The key to reducing false positives is maintaining
a baseline of known-good scheduled tasks and alerting only on
deviations from that baseline.
